# AI Studio

Office 365처럼 쓰고, AI가 읽을 수 있게 저장하는 오피스 스위트.
**Rust로 만들어 어느 운영체제에서든 파일 하나 내려받아 실행합니다.**

| 앱 | 대응 | 확장자 | 저장 방식 |
|---|---|---|---|
| **AI Deck** | PowerPoint | `.aideck` | 슬라이드마다 `내용.md` + `배치.layout.json` |
| **AI Doc** | Word | `.aidoc` | 섹션마다 `내용.md` + `서식.meta.json` |
| **AI Grid** | Excel | `.aigrid` | 시트마다 `투영.md` + `셀.cells.json` |

핵심 아이디어는 하나입니다. **내용은 Markdown에, 배치·계산은 JSON에** 나누어 담고, 저장할 때마다
프로젝트 전체를 요약한 `AI.md`를 함께 생성합니다. `.pptx`처럼 zip 안에 XML을 숨기지 않으므로
`git diff`, `grep`, RAG 인덱서가 모두 그대로 동작합니다.

**쓰는 방식은 Office와 같습니다.** 도형 갤러리도, 표 격자 선택기도, 리본도 같은 자리에 같은
이름으로 있습니다. 도형의 어휘 자체가 OOXML의 프리셋 이름(`roundRect`, `flowChartDecision`,
`rightArrow` …)이기 때문에, **기존 `.pptx` · `.docx` · `.xlsx`를 열면 그 모양 그대로 보입니다.**
바뀌는 것은 저장 방식뿐입니다.

포맷 전체 스펙은 [`docs/FORMAT.md`](docs/FORMAT.md), 구조는 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)에 있습니다.

## 기존 파일 열기

시작 화면의 **기존 파일 열기**를 누르거나, 창에 파일을 끌어다 놓습니다.

| 원본 | 결과 | 좌표 |
|---|---|---|
| `.pptx` | `.aideck` | **정확히 일치** (EMU ÷ 914400 × 96) · 4:3·세로·임의 크기 모두 그 크기로 |
| `.xlsx` | `.aigrid` | 수식(공유·시트 간)·표시 형식·스타일·글자 크기·병합·틀 고정·이름 범위·차트 |
| `.docx` | `.aidoc` | 제목 단계·목록·인용·표·**용지 크기와 방향**·여백·문단 서식 |

**원본 파일은 건드리지 않습니다.** 폴더 문서를 새로 만들고, 돌아가는 길은 내보내기입니다.
제자리에서 고쳐 다시 `.pptx`로 저장한다면 이 포맷이 존재하는 이유가 없어지기 때문입니다.

pptx에서 넘어오는 것: 자리틀에서 상속한 좌표(대부분의 실제 덱에서 제목 도형은 자기 좌표가
없습니다), 도형 프리셋·채우기·윤곽선·회전·반전, 테마 색, 마스터의 글머리 기호, 표(열 너비·병합·
정렬), 네이티브 차트의 숫자, 그림, 발표자 노트, 그룹 좌표 변환.

### 원본대로 보이게 하는 것들

실제 파일은 서식을 자기 안에 적어 두지 않습니다. **레이아웃과 마스터에 적혀 있습니다.**
그것을 읽지 않으면 열리기는 하지만 원본처럼 보이지 않습니다.

| | 원본이 서식을 적어 둔 곳 | 읽지 않으면 |
|---|---|---|
| **글자 크기** | 마스터의 `titleStyle` 44pt · `bodyStyle` 32/28/24pt · `otherStyle` 18pt (레이아웃이 자리틀별로 덮어씀) | 모든 글자가 앱 기본 크기로 |
| **디자인 요소** | 레이아웃·마스터의 띠·선·로고 도형 | 흰 바탕에 글자만 |
| **배경색** | 보통 레이아웃의 `p:bg`, 슬라이드에는 없음 | 어두운 테마 덱이 흰색으로 |
| **글자색** | 테마의 `dk1`을 `sysClr windowText`로 (모든 Office 테마가 이렇게) | 검정이 사라짐 |
| **자동 맞춤** | `normAutofit fontScale="62500"` — PowerPoint가 줄여 넣은 기록 | 이미 자리가 부족했던 도형이 넘침 |
| **용지 크기** | Word의 `pgSz` — 가로 방향이거나 아예 임의 크기일 수 있음 | A4로 되돌려져 전체가 다시 흐름 |
| **셀 글자 크기** | Excel의 폰트 테이블 | 큰 제목 행이 본문 크기로 |
| **끌어 만든 수식** | `<f t="shared" si="0"/>` — 텍스트는 첫 셀에만 | 드래그로 채운 셀 전부가 수식을 잃음 |
| **시트 간 참조** | `=실적!B4`, 다른 시트를 가리키는 이름 | 요약 시트가 통째로 깨짐 |
| **워크북 차트** | `xl/charts/` + 드로잉 앵커 | 저자가 가장 공들인 것이 사라짐 |
| **머리글·바닥글** | Word의 별도 파트 + `PAGE` 필드 | 페이지 번호가 없어짐 |
| **변경 내용·콘텐츠 컨트롤·텍스트 상자** | `w:ins` · `w:sdt` · `w:txbxContent` | 그 안의 글이 전부 사라짐 |

`showMasterSp="0"`(마스터 도형 숨김)과 `b="0"`(굵게 해제)처럼 **"아니라고 말한 것"** 도
"말하지 않은 것"과 구분해서 읽습니다. 구분하지 않으면 전면 이미지 슬라이드 위에 띠가 그려지고,
굵게를 끈 제목이 다시 굵어집니다.

### 똑같이 못 할 것은 **가장 가까운 것으로 바꿉니다**

없는 기능이라고 지우면, 열어 본 사람에게는 그냥 사라진 것입니다. 그래서 이 프로그램에 없는 것은
있는 것 중 가장 가까운 모양으로 바꿉니다.

| 원본 | 이 앱에서 |
|---|---|
| **SmartArt** | 같은 모양·색·글자의 **도형들** — Office가 파일 안에 함께 그려 둔 도형을 그대로 씁니다 (그것도 없으면 글머리 목록으로) |
| **OLE 개체** (수식·워크북·PDF) | Office가 그 자리에 그려 둔 **미리보기 그림** |
| **사진으로 채운 도형** | 그 **사진** (도형 테두리는 잃습니다) |
| **그라데이션 채우기** | **중간 색**의 단색 — 첫 색을 쓰면 원본보다 너무 밝거나 어둡습니다 |
| **분산형·방사형·거품형·주식형·3차원 차트** | **꺾은선/막대 차트** — 숫자는 그대로, 축만 다릅니다 |
| **마스터의 바닥글·날짜·슬라이드 번호** | **텍스트 블록** — 번호는 `‹#›`이 아니라 그 슬라이드의 실제 번호 |
| **조건부 서식** | 저장된 값 기준의 **고정 서식** — 음수는 빨갛게, 색조는 보간한 배경색으로 |
| **Word 각주·미주** | 문장에 **¹** 표시 + 구분선 아래 작은 글씨로 모음 (Word가 페이지 아래에 두는 것과 같은 배치) |
| **Word 머리글·바닥글 필드** | `{PAGE}` 토큰 — 페이지마다 치환되고, 내보내면 다시 Word의 필드가 됩니다 |
| **2단·3단 문서** | 실제 **다단 조판** (Word와 같은 48px 간격), 페이지 나눔도 단 수만큼 |
| **문단 음영** | 문단 **배경색** |
| **변경 내용·콘텐츠 컨트롤·텍스트 상자** | 본문 텍스트 (지운 텍스트는 제외) |
| **표 안의 표** | 그 셀 안의 **줄들** |
| **워크북 차트** | **범위를 가리키는 살아 있는 차트** (값 복사가 아니라) |

바꾸지 못한 것은 그대로 알려 줍니다 — 데이터 막대·아이콘 집합(셀 안에 그리는 그림), 화면 전환과
애니메이션, 숨긴 행·열(숨김을 표현할 방법이 없어 그대로 보입니다), 데이터 유효성 검사, 자동 필터,
검토 주석, 시트 안의 그림.

### 무엇이 바뀌었는지 열기 전에 보여줍니다

바꾼 것이 있으면 **가져오기 보고**가 먼저 뜹니다 — Word가 옛 형식을 변환할 때 띄우는 것과 같은
자리입니다. 토스트로 스쳐 지나가면 여섯 줄을 읽을 시간이 없고, 그 여섯 줄이 바로 "원본과 다르게
보이는 부분"입니다.

```
가져왔습니다 — 바뀐 것
  · 화면에서는 글꼴을 Pretendard로 표시합니다 (Calibri, 맑은 고딕) — 내보낼 때는 원래 글꼴 이름을 유지합니다
  · SmartArt는 같은 모양의 도형들로 바꿨습니다
  · 조건부 서식은 저장된 값 기준의 고정 서식으로 바꿨습니다
  · 데이터 막대·아이콘 집합은 표현할 방법이 없어 넘어갔습니다
                                                      [취소] [열기]
```

### 16:9가 아닌 덱도 그 크기로 열립니다

사람들은 온갖 크기로 만듭니다 — 프로젝터용 4:3, 인쇄용 A4 세로, 정사각형, 그리고 직접 입력한 크기.
`p:sldSz`를 읽어 **캔버스를 그 크기로** 만들고, 왼쪽 썸네일도 그 비율로 그립니다. 16:9로 늘어난
썸네일은 파일이 잘못 열렸다는 것을 가장 먼저 알려주는 신호입니다.

| 파일 | 캔버스 |
|---|---|
| 와이드스크린 13.333×7.5in | 1280 × 720 |
| 표준 4:3 10×7.5in | 960 × 720 |
| A4 세로 유인물 | 745 × 1056 (창에 맞춤이 **높이** 기준으로) |
| 직접 입력한 24×18cm | 907 × 680 |

**디자인 탭**에서 PowerPoint의 크기(와이드스크린·표준·A4 가로/세로·Letter·정사각형)를 고르거나
너비·높이를 px로 직접 넣을 수 있고, 옆에 비율(`4:3`, `1.42 : 1`)이 함께 표시됩니다. 크기를 바꿀 때
내용은 **배율을 조정하지 않고** 캔버스를 벗어나는 것만 안으로 들입니다 — PowerPoint의 "맞춤 확인"과
같은 쪽입니다.

파일이 만들어진 뒤 크기만 바뀐 경우(PowerPoint 아닌 도구가 흔히 그렇게 합니다)에는 레이아웃의
자리틀이 옛 크기에 맞춰져 있습니다. **상속한** 좌표가 캔버스를 넘치면 안으로 들여 그립니다 — 745px
슬라이드에 864px 제목은 보여줄 방법이 없기 때문입니다. 도형이 스스로 말한 좌표는 손대지 않습니다:
반쯤 걸쳐 놓은 사람은 그러려고 그런 것입니다.

### 메뉴는 리본에 갇히지 않습니다

리본은 창이 좁아지면 가로로 스크롤됩니다(`overflow-x: auto`). 그래서 리본 안에 그린 메뉴는
**리본 높이에서 잘렸습니다** — 색 팔레트도, 도형 갤러리도, 표 격자도.

메뉴는 이제 페이지(`document.body`)에 그려지고, 자기를 연 단추의 화면 위 위치에 맞춰 붙습니다.
아래로 자리가 없으면 위로 뒤집고, 오른쪽으로 넘치면 왼쪽으로 당기고, 스크롤하면 따라옵니다.
바깥을 누르거나 `Esc`를 누르거나 단추를 다시 누르면 닫힙니다 — 세 가지 모두 사람들이 시도하는
방법입니다.

### 색은 Office의 팔레트로 고릅니다

리본에 고정된 견본 여섯 개는 Office를 흉내낸 것처럼 보이게 만드는 바로 그 지점입니다. 그래서 색
단추는 Office와 같은 **분할 단추**입니다 — 현재 색을 보여주는 견본을 누르면 팔레트가 열립니다.

- **테마 색** 10열 × 6행 — 배경·텍스트·강조 6색과, 각각의 밝게 3단계·어둡게 2단계
- **표준 색** 10개 — Office가 처음부터 쓰던 그 열
- **채우기 없음 / 윤곽선 없음 / 자동** — 색을 지우는 명시적인 항목 (Office와 같은 빨간 사선 견본)
- **다른 색…** — 시스템 색 선택기로 아무 색이나

첫 강조색은 이 문서의 강조색(`manifest.theme.accent`)이고, 나머지는 내보내는 `.pptx` 테마가 쓰는
색과 같습니다 — 여기서 고른 색은 PowerPoint에서 열어도 같은 색입니다. 도형 채우기·윤곽선, 글자 색,
셀 채우기, 표 음영, 슬라이드 배경이 모두 같은 팔레트를 씁니다. 선택한 것이 없으면 색 단추는
Office처럼 잠깁니다 — 눌러도 아무 일이 없는 단추보다 잠긴 단추가 정직합니다.

### 글꼴은 하나로 바뀝니다

원본은 Calibri·맑은 고딕·바탕을 저마다 요구하지만, 읽는 사람의 컴퓨터에 그 글꼴이 있을지는
알 수 없습니다. 그래서 이 앱은 **글꼴이 하나**입니다 — [Pretendard](https://github.com/orioncactus/pretendard)
(SIL OFL 1.1)를 앱에 담아 배포하므로, Windows·macOS·Linux에서 그리고 네트워크가 없어도
같은 모양으로 열립니다. 내보내는 `.docx`·`.pptx`·`.xlsx`도 같은 글꼴을 적어 나갑니다.

바꾼 글꼴은 조용히 넘기지 않고 알려 줍니다 — "화면에서는 글꼴을 Pretendard로 표시합니다
(Calibri, 맑은 고딕)".

옮겨지지 않는 것도 침묵하지 않고 알립니다 — "그라데이션 채우기는 첫 색으로 단순화했습니다",
"SmartArt·OLE 개체는 가져오지 못했습니다".

## 받아서 실행하기

[Releases](../../releases)에서 OS에 맞는 파일을 내려받습니다. **런타임을 따로 설치할 필요가 없습니다** —
문서 코어(수식 엔진, 저장 포맷, `AI.md` 생성, Office 내보내기) 전체가 실행 파일 안에 컴파일되어 있습니다.

| OS | 파일 | 실행 |
|---|---|---|
| Windows 10+ | `AI.Studio_0.2.0_x64-setup.exe` 또는 `.msi` | 설치 후 시작 메뉴에서 |
| macOS 12+ | `AI.Studio_0.2.0_aarch64.dmg` (Intel은 `x64`) | 드래그해 설치 |
| Linux | `ai-studio_0.2.0_amd64.AppImage` | `chmod +x` 후 실행. `.deb` · `.rpm`도 있습니다 |

문서는 기본적으로 `~/Documents/AI Studio` 에 저장됩니다. 다른 위치를 쓰려면
`AI_STUDIO_WORKSPACE=/경로` 를 지정하세요.

### 서버로 쓰기

브라우저에서 열거나, 공유 장비에 두거나, 에이전트가 UI 없이 문서를 다루게 하려면
`ai-studio-serve` 바이너리 하나만 두면 됩니다. 웹 UI가 내장되어 있습니다.

```bash
./ai-studio-serve --workspace ./documents --open
# http://localhost:5177
```

```
--workspace <경로>   문서 폴더 (기본 ./workspace, 환경변수 AI_STUDIO_WORKSPACE)
--port <번호>        수신 포트 (기본 5177, 환경변수 PORT)
--host <주소>        수신 주소 (기본 127.0.0.1). 0.0.0.0은 네트워크에 노출됩니다
--web <경로>         빌드된 웹 UI 폴더 (내장본보다 우선)
--token <문자열>     API 접속 토큰 (환경변수 AI_STUDIO_TOKEN)
--tokens <파일>      이름 있는 토큰 목록 (한 줄에 `이름:역할:토큰`, 역할은 read/write)
--open               시작 후 브라우저를 엽니다
```

`--token` 을 지정하면 모든 `/api` 요청에 `Authorization: Bearer <토큰>` 이 필요합니다
(헤더를 실을 수 없는 내보내기 다운로드와 이미지는 `?token=`). 웹 UI는 처음 401을 만나면
토큰을 물어 저장합니다. 팀으로 쓰려면 `--tokens 파일`로 **이름 있는 토큰**을 나눠 줍니다 —
`읽기` 토큰은 문서를 읽고 내보내고 계산(`/recalc`·`preview`)할 수 있지만 고치지 못합니다
(403에 토큰 이름이 함께 나옵니다). RAG 인덱서에는 읽기 토큰이면 충분합니다.

```
# tokens.txt — 이름:역할:토큰
지민:write:8f3k...
인덱서:read:2mv9...
``` 토큰 없이 `--host 0.0.0.0` 으로 띄우면 같은 네트워크의 누구나 문서를
읽고 쓸 수 있다는 경고가 출력됩니다 — 신뢰하는 망이 아니라면 토큰을 쓰거나 앞에 리버스
프록시를 두세요. HTTPS가 필요하면 리버스 프록시에서 종단하세요.

### 스프레드시트가 특히 다릅니다

`.cells.json`이 계산의 원천이고, `.md`는 AI가 읽는 투영입니다. 표에는 **계산된 값**이 열 문자(A·B·C)와
행 번호와 함께 들어가고, 그 아래에 **수식과 결과가 짝으로** 붙습니다.

```markdown
|     | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| **1** | **항목** | **10월** | **11월** | **12월** | **분기 합계** | **비중** |
| **2** | 인건비 | ₩480,000,000 | ₩495,000,000 | ₩495,000,000 | ₩1,470,000,000 | 48.0% |

### 수식
- `E2` = `=SUM(B2:D2)` → ₩1,470,000,000
- `F2` = `=E2/$E$7` → 48.0%

### 열 요약
집계 대상: 2–7행 (집계 행 7행 제외)

| 열 | 머리글 | 유형 | 값 개수 | 합계 | 평균 | 최소 | 최대 |
|---|---|---|---|---|---|---|---|
| B | 10월 | 숫자 | 5 | 964,000,000 | 192,800,000 | 46,000,000 | 480,000,000 |
```

덕분에 AI는 `"D4의 합계는?"`, `"비중이 가장 큰 항목은?"` 같은 질문에 **셀 주소로** 답할 수 있습니다.
열 요약은 합계 행을 제외하고 계산하므로 시트 자체의 합계와 항상 일치합니다 — 틀린 숫자를 주는 요약은
없는 요약보다 나쁘기 때문입니다.

### 함수는 Excel의 것을 씁니다

**215개**를 계산합니다. Excel의 리본과 같은 범주로 나뉘어 있고, 이름과 인수 순서도 같습니다.

| 범주 | 있는 것 |
|---|---|
| **재무** | `PMT` `FV` `PV` `NPER` `RATE` `NPV` `IRR` `IPMT` `PPMT` `SLN` `SYD` `DDB` |
| **찾기/참조** | `VLOOKUP` `HLOOKUP` `XLOOKUP` `XMATCH` `INDEX` `MATCH` `LOOKUP` `CHOOSE` `OFFSET` `INDIRECT` `ROW` `COLUMN` `ADDRESS` `TRANSPOSE` `UNIQUE` `SORT` `FILTER` `SEQUENCE` |
| **통계** | `SUMIFS` `COUNTIFS` `AVERAGEIFS` `MAXIFS` `MINIFS` `LARGE` `SMALL` `RANK` `PERCENTILE` `QUARTILE` `STDEV.S/P` `VAR.S/P` `CORREL` `SLOPE` `INTERCEPT` `FORECAST` `SUBTOTAL` `AGGREGATE` `TRIMMEAN` |
| **날짜** | `EDATE` `EOMONTH` `DATEDIF` `YEARFRAC` `NETWORKDAYS` `WORKDAY` `WEEKNUM` `ISOWEEKNUM` `TIME` `HOUR` `MINUTE` `SECOND` `DAYS360` |
| **텍스트** | `SEARCH` `REPLACE` `REPT` `CHAR` `CODE` `EXACT` `TEXTBEFORE` `TEXTAFTER` `FIXED` `DOLLAR` `NUMBERVALUE` |
| **수학** | `MROUND` `CEILING.MATH` `FLOOR.MATH` `QUOTIENT` `GCD` `LCM` `FACT` `COMBIN` `PERMUT` `EVEN` `ODD` `LOG` 삼각함수 전체 |
| **논리·정보** | `SWITCH` `XOR` `ISEVEN` `ISODD` `ISERR` `ISNA` `ISLOGICAL` `N` `TYPE` `ERROR.TYPE` |

값은 Excel과 자리 넷까지 맞춰 검사합니다 — 3억 원 30년 5% 대출의 `PMT`는 -1,610,464.869원입니다.

**시트를 넘는 참조도 계산합니다.** `=실적!B4`, `=SUM('2분기 실적'!A1:D9)`, 그리고 다른 시트를
가리키는 이름 있는 범위까지. 요약 시트는 대개 이것으로만 만들어져 있으므로, 이게 없으면
요약 시트는 열려도 비어 보입니다.

배열을 다루는 옛 관용구도 그대로 동작합니다 — `=SUMPRODUCT((A2:A7="서울")*C2:C7)`.

**동적 배열은 흘러넘칩니다.** `=UNIQUE(A2:A7)`을 넣으면 결과가 아래 빈 셀로 펼쳐지고, 펼쳐질
자리에 무엇이 있으면 Excel처럼 `#SPILL!`이 됩니다. 펼쳐진 셀을 고르면 앵커의 수식이 수식
입력줄에 회색으로 보이고 스필 범위에 테두리가 그려지며, 그 위에 직접 입력하면 스필이 깨집니다 —
전부 Excel의 동작 그대로입니다. 파일에는 앵커에 `spill` 범위가, 펼쳐진 셀에 계산된 값이
적히므로(`spillFrom`) 계산 엔진 없이 읽는 AI도 정확한 값을 봅니다. 내보낸 `.xlsx`에서는 배열
수식(`t="array"`)으로, 가져올 때도 그대로 복원됩니다. 스필 범위 전체는 `=SUM(E2#)`처럼
**`#` 연산자**로 참조합니다 — 스필이 자라면 참조도 따라 자라고, 행을 삽입하면 `E2#`도 함께
이동하며, 내보낸 파일에는 Excel의 저장 형태(`_xlfn.ANCHORARRAY`)로 나갑니다.

### 계산하지 못하는 수식은 파일의 값을 남깁니다

없는 함수나 넘겨받지 못한 시트를 만나면, **셀에 이미 있던 값을 그대로 둡니다.** 남의 워크북을
열었다가 숫자가 `#REF!`로 바뀌는 것보다, 다시 구해내지 못한 값을 그대로 보여주는 편이 낫습니다 —
그 숫자는 파일이 말한 것이고, 사람들은 그 숫자를 보러 온 것입니다. 무엇이 그랬는지는 가져올 때
알려 줍니다: "함수 XIRR는 계산하지 않습니다 (수식과 저장된 값은 그대로 둡니다)".

### 표시 형식도 Excel의 것을 읽습니다

`#,##0_);[Red](#,##0)`처럼 **음수·0·텍스트 구역**이 나뉜 형식, `yyyy"년" m"월"`처럼 따옴표로 묶은
글자, `[$₩-412]`같은 통화·로케일 괄호, `ddd`·`dddd`·`mmm`(요일과 월 이름), `h:mm AM/PM`,
`0.00E+00`, 뒤에 붙은 쉼표로 천 단위 줄이기, `@` 텍스트 자리까지 렌더링합니다. 회계 형식으로 된
금액이 `(45,900)`이 아니라 `-45900`으로 보이면 그 시트는 원본과 다른 시트입니다.

### 차트도 그림이 아니라 숫자로 저장됩니다

차트는 Deck·Doc에서는 ```` ```chart ```` 블록, Grid에서는 셀 범위를 가리키는 부동 개체입니다.
어느 쪽이든 `.md`와 `AI.md`에는 **차트를 그리는 숫자가 표로** 들어갑니다.

```markdown

- 세로 막대 차트 "분기별 매출" — 계열 2개(2025, 2026), 항목 4개 (범위 `A1:D5`)

  | 구분 | 2025 | 2026 |
  |---|---|---|
  | 1분기 | 98 | 120 |
```

## 마크다운을 직접 고쳐도 됩니다

이 포맷은 단방향이 아닙니다.

- **슬라이드 md에 블록을 손으로 추가**하면 다음에 열 때 자동 레이아웃을 받아 나타납니다.

  갖고, 서식을 되돌리면 앵커도 사라집니다.
- **차트의 셀 범위가 깨져도** 스펙에 남은 값으로 그립니다.

즉 AI 에이전트가 마크다운만 써서 문서를 만들거나 고칠 수 있습니다.

md/json과 `AI.md`가 다시 쓰입니다. 제목을 바꾸면 폴더 이름도 따라갑니다.

**저장할 때마다 직전 상태가 `.history/`에 보관됩니다** (최근 30개). 파일 탭의 **버전 기록**에서
아무 버전으로나 되돌릴 수 있고, 복원할 때도 지금 상태를 먼저 보관하므로 복원 자체를 되돌릴 수
있습니다. 보관본도 같은 md/json이라 `diff`로 두 버전을 비교할 수 있습니다.

**`F1`을 누르면 그 앱의 단축키 전체가 나옵니다.** Office에서 손에 익은 것이 여기서도 되는지
확인하는 가장 빠른 길이고, 그 목록에 없는 것은 없는 것입니다. 세 앱 모두 **서식 복사**(🖌)가
클립보드 그룹에 있어, 서식만 집어 다른 셀·문단·개체에 붙일 수 있습니다.

**삽입** — 리본은 Office 순서 그대로 **표 · 이미지 · 일러스트레이션 · 텍스트**입니다.

**도형**은 Office와 같은 갤러리입니다. 선 · 사각형 · 기본 도형 · 블록 화살표 · 수식 도형 ·
순서도 · 별 및 배너 · 설명선 8개 서랍에 프리셋 136개가 Office의 한국어 이름으로 들어 있고,
검색되고, 최근 사용한 도형이 위에 남습니다. 고르면 **커서가 십자로 바뀌고 슬라이드에 끌어
그립니다** — 그냥 누르면 기본 크기로 놓입니다 (`Esc`로 취소). 넣은 뒤에는 **회전 핸들**로 돌리고
(`Shift`로 15°씩), **노란 조절 핸들**로 모양을 바꿉니다 — 둥근 사각형의 모서리 반경, 화살표의
축 두께와 머리 길이, 삼각형의 꼭대기, 설명선의 꼬리 같은 것들입니다.

**표**는 격자를 훑어 크기를 고르고 누르면 삽입됩니다. 셀을 누르면 표가 선택되고 커서가 들어가며,
`Tab`으로 다음 셀(마지막 셀에서는 행이 추가됩니다), `Shift+Tab`으로 이전 셀, 화살표로 이동,
아무 글자나 입력하면 편집 시작, `F2`로 수정, `Shift+Enter`로 셀 안 줄바꿈 — 전부 Office와
같습니다. 표는 둘러싼 테두리를 끌어 옮깁니다.

**상황별 탭** — 도형을 고르면 **도형 서식**(도형 삽입 · 도형 채우기 · 도형 윤곽선 · 회전 · 정렬 ·
크기), 표를 고르면 **표 디자인**(표 스타일 옵션 · 표 스타일 · 음영)과 **레이아웃**(행 및 열 ·
삭제 · 병합 · 맞춤 · 셀 크기)이 리본 오른쪽에 붙고, 선택을 놓으면 사라집니다.

**Deck** — 블록을 끌어 옮기고 8방향 핸들로 크기를 바꿉니다. 다른 블록과 캔버스 중심선에 스냅되며
(`Alt`로 해제), 화살표키로 8px씩(`Ctrl` 또는 `Shift`와 함께 1px씩) 이동하고 `Alt+화살표`로 크기를
바꿉니다. `Tab`/`Shift+Tab`은 슬라이드의 개체를 차례로 선택합니다 — 뒤에 깔린 도형도 앞의 것을
치우지 않고 고를 수 있고, **`Alt+클릭`**은 그 자리에서 겹친 요소를 하나씩 아래로 내려가며 골라
주며(우클릭 메뉴에 **뒤에 있는 요소** 목록이 함께 나옵니다), 블록은 **캔버스 밖으로도** 놓을 수
있습니다. 블록을 두 번 누르면 그려진 텍스트가 곧 편집면이 되어 그 자리에서 고치고,
`Ctrl+B`/`Ctrl+I`가 `**`/`*`를, `Ctrl+L`/`E`/`R`/`J`가 문단 맞춤을, `Ctrl+Shift+>`/`<`가 글자 크기를
바꿉니다. 단락 그룹에 **줄 간격**이 있고, 내보낼 때 PowerPoint의 `a:lnSpc`가 됩니다.
`Ctrl+M`으로 새 슬라이드, `Ctrl+C`/`X`/`V`/`D`로 요소를 복사·잘라내기·붙여넣기·복제하고, 개체 순서는
**맨 앞으로 · 앞으로 · 뒤로 · 맨 뒤로** 네 단계입니다. 축소판에서 `Delete`로 슬라이드를 지우고
`Ctrl+화살표`로 순서를 바꿉니다.
**`F5`로 처음부터, `Shift+F5`로 현재 슬라이드부터 슬라이드 쇼**를 시작하면 `→`/`Space`로 이동,
`S`로 발표자 노트, `B`/`W`로 검은 화면·흰 화면, `Esc`로 종료합니다. 쇼는 캔버스와 같은 렌더러를
쓰므로 **도형은 그 도형으로, 표는 그 표로** 보입니다.

**Doc** — **페이지 전체가 한 장의 연속 편집면입니다.** 문단마다 편집 상자가 열리는 것이 아니라
페이지의 어디든 클릭하면 그 자리에 캐럿이 놓이고, 문단 경계를 넘어 드래그한 텍스트도 그대로
선택·복사됩니다. 그려진 문단 그 자체가 편집면이어서 클릭해도 글자가 줄어들거나 튀지 않고,
마크다운 기호(`#`, `**`, `-`)는 화면에 나타나지 않습니다 — 저장 포맷은 그대로 마크다운이지만,
편집기는 그려진 형태만 보여 주고 입력한 내용을 스스로 마크다운으로 되돌립니다. `#`+공백을
문단 맨 앞에서 치면 그 순간 제목이 되고, `-`+공백은 목록, `>`+공백은 인용, `---`은 구분선이
됩니다 — Word의 자동 서식과 같은 방식입니다. 선택 문단은 왼쪽에 가는 색 막대만, 편집 중인
문단만 아주 연한 배경입니다. 페이지의 빈 곳을 두 번 누르면 그 페이지 끝에 새 문단이 생기고
바로 입력할 수 있습니다. 문단을 나누려면 `Enter`, 같은 문단 안에서 줄을 바꾸려면
`Shift+Enter` — Word와 같습니다. 목록 안에서는 `Enter`가 다음 항목을 만들고, 빈
항목에서 한 번 더 누르면 목록을 나가 새 문단이 됩니다. 문단 맨 앞에서 `Backspace`는 이전
문단과 합칩니다(제목 맨 앞에서는 제목 서식만 벗겨서 합칩니다). **`↑`/`↓`는 문단 경계를
넘어갑니다** — 눌러 두면 문서 전체를 훑을 수 있습니다. `Tab`/`Shift+Tab`은 들여쓰기이고,
목록 안에서는 수준을 바꿉니다(포커스가 문서를 벗어나지 않습니다).

Word의 서식 단축키가 그대로 동작합니다: `Ctrl+B`/`I`/`U`, `Ctrl+L`/`E`/`R`/`J`(맞춤),
`Ctrl+1`/`5`/`2`(줄 간격 1.0·1.5·2.0), `Ctrl+Alt+1~3`(제목), `Ctrl+Shift+N`(본문),
`Ctrl+Shift+>`/`<`(글자 크기), `Ctrl+K`(하이퍼링크), `Ctrl+Home`/`End`(문서 처음·끝).
**밑줄과 형광펜, 줄 간격, 문단 위·아래 간격**은 마크다운에 표기가 없으므로 문단의 `.meta.json`에
기록되고, 내보낼 때 Word의 `w:u`·`w:shd`·`w:spacing`이 됩니다.

블록 높이를 실제로 측정해 **A4/Letter/A5 페이지로 나누고**, `Ctrl+Enter`로 페이지 나누기를 넣고,
`Ctrl+P`로 인쇄/PDF를 냅니다. `Ctrl+F`/`Ctrl+H`로 찾기·바꾸기.

**`Ctrl+P`는 세 앱 모두에서 동작합니다.** Deck은 슬라이드마다 한 장씩 덱 비율에 맞는 방향으로,
Grid는 사용 중인 범위를 Excel의 기본 인쇄처럼(눈금선·머리글 없이, 지정한 서식만) 종이에 올립니다.
브라우저의 인쇄 대화상자에서 PDF로 저장하면 그것이 이 앱의 PDF 내보내기입니다.

**Grid** — 화살표/`Tab`/`Enter`로 이동, 아무 글자나 입력하면 편집 시작, `F2`로 수정, `Delete`로 지우기.

**큰 시트를 손으로 훑지 않습니다.** `Ctrl+화살표`는 데이터 끝으로 건너뛰고, `Ctrl+Shift+화살표`는
거기까지 선택하고, `Ctrl+Home`/`Ctrl+End`는 `A1`과 마지막 데이터 셀로, `Home`/`End`는 행의 처음과
마지막 데이터 열로 갑니다. `PageUp`/`PageDown`은 한 화면씩, `Ctrl+PageUp`/`PageDown`은 시트를
넘깁니다. `Ctrl+A`는 커서가 있는 데이터 블록을, 한 번 더 누르면 시트 전체를 선택하고,
`Ctrl+Space`/`Shift+Space`는 열·행 전체를 잡습니다.

입력 쪽은 `Alt+Enter`로 셀 안에서 줄을 바꾸고, `F4`로 수식의 참조를 `A1` ↔ `$A$1`로 돌리고,
`Ctrl+D`/`Ctrl+R`로 아래·오른쪽으로 채우고, `Ctrl+Enter`로 선택 영역을 같은 값으로 메우고,
`Ctrl+;`/`Ctrl+Shift+;`로 오늘 날짜와 지금 시각을 넣습니다. 서식은 `Ctrl+1`(셀 서식),
`Ctrl+Shift+1`/`4`/`5`(쉼표·통화·백분율), 리본의 **자릿수 늘림·줄임**과 **텍스트 줄바꿈**(행 높이도
함께 맞춥니다) · **세로 맞춤**이 있고, 줄바꿈과 세로 맞춤은 내보낸 `.xlsx`의 `<alignment>`가 됩니다.

선택 영역 우하단의 **자동 채우기 핸들**을 끌면 등차수열·수식(상대 참조 이동)·`ID-008`류 텍스트가
이어집니다. 열/행 경계를 끌어 크기를 바꾸고(두 번 누르면 자동 맞춤 — 행도 마찬가지),
머리글을 끌면 여러 행·열이 선택되고, 여러 행을 고른 뒤 삽입하면 **그만큼 삽입됩니다**.
시트 탭은 끌어서 순서를 바꿉니다. **이름 상자**에 `D3`이나 범위 이름을 입력해 이동하고,
셀 병합·테두리·틀 고정이 동작합니다.

**정렬**은 커서가 있는 열을 기준으로 그 데이터 블록 전체를 정렬하고, 첫 행이 제목처럼 보이면
(글자 위의 숫자, 또는 굵은 첫 행) 그 행은 제자리에 둡니다 — 판단은 `머리글 행` 체크박스로 바꿀
수 있습니다. 눈에 보이는 셀만 정렬해 행이 어긋나는 일은 없습니다.

`Ctrl+C`는 값을, `Ctrl+Shift+C`는 수식을 TSV로 복사하므로 Excel과 오갈 수 있습니다.
`Ctrl+V`는 TSV와 마크다운 표를 모두 붙여넣습니다.
`` Ctrl+` ``로 수식 보기를 켜고, 수식 셀을 고르면 참조하는 셀에 테두리가 표시됩니다. 행/열을
삽입·삭제하면 수식 참조가 자동으로 따라갑니다.

오른쪽 **`{ } 저장 포맷`** 패널은 지금 이 순간 디스크에 쓰일 md와 json을 그대로 보여줍니다.
제목줄의 **`{ } 저장 포맷`** 단추나 패널 머리의 **✕**로 열고 닫을 수 있습니다.
패널과 저장 경로가 **같은 Rust 직렬화기**를 쓰기 때문에 실제 저장될 내용과 바이트 단위로 같습니다.

Doc의 **삽입** 탭에는 Office처럼 **머리글 및 바닥글** 그룹이 있습니다. `페이지 번호`는 한 번
누르면 바닥글 가운데에 페이지 번호가 들어가고, `머리글`·`바닥글`은 왼쪽·가운데·오른쪽 세 칸을
직접 채웁니다. `{PAGE}` · `{PAGES}` · `{DATE}`는 페이지마다 치환되고, 내보낼 때 **Word의 필드**가
되므로 페이지가 늘어나도 번호가 맞습니다. 화면 아래 `1 / 3` 표시는 편집용이라 인쇄되지 않고,
머리글·바닥글은 인쇄됩니다.

Doc의 **레이아웃** 탭은 Word 순서 그대로 여백 · 용지 방향 · 용지 크기입니다. 용지 방향과 용지
크기는 서로를 되돌리지 않습니다 — 가로 상태에서 `Letter`를 고르면 가로 Letter가 됩니다. 목록에
없는 크기는 `크기 (px)`에 직접 넣을 수 있고, 그러면 용지 이름이 `사용자 지정`으로 바뀝니다.
Deck의 **디자인** 탭에는 PowerPoint와 같은 와이드스크린(16:9)·표준(4:3)이 있고, 가져온 덱이
둘 중 어느 것도 아니면 그 크기가 목록에 함께 나타납니다.

## 구조

```
crates/ai-formula/     수식 엔진 — 렉서, 파서, 평가기, 함수 215개, 시트 간 참조, 표시 형식
  library/             함수 가족별 모듈 — 수학·텍스트·날짜·통계·재무·찾기·정보
crates/ai-format/      포맷 — md/json 파싱·직렬화, AI.md 생성, 차트 스펙, 파일 I/O
crates/ai-export/      OOXML 작성기 — pptx(네이티브 차트) · docx · xlsx(살아있는 수식) · csv
crates/ai-import/      OOXML 판독기 — pptx · docx · xlsx를 이 포맷으로
crates/ai-core/        하나뿐인 API 표면 — 데스크톱과 서버가 함께 씁니다
crates/ai-studio-app/  Tauri 데스크톱 앱
crates/ai-studio-serve/ axum 헤드리스 서버 (웹 UI 내장 가능)
crates/ai-studio-wasm/ 같은 코어를 브라우저용 WebAssembly로
apps/web/              React — 런처 + 세 에디터. 뷰 코드만 들어 있습니다
templates/             샘플 문서 — 이 프로젝트가 정의하는 포맷 그 자체로 저장
docs/FORMAT.md         포맷 스펙
docs/ARCHITECTURE.md   왜 이렇게 나누었는가
```

**문서 로직의 구현은 하나뿐입니다.** 수식 엔진도, 저장 포맷도, `AI.md` 생성기도 Rust에만 있습니다.
데스크톱 앱은 Tauri 커맨드로, 서버는 HTTP로, 브라우저 에디터는 WebAssembly로 **같은 크레이트**를
호출합니다. 그래서 `{ } 저장 포맷` 패널이 보여주는 내용과 디스크에 쓰이는 바이트가 어긋날 수 없습니다.

에디터에 남아 있는 JavaScript는 뷰 코드입니다 — 차트와 도형의 SVG 그리기, 마크다운→HTML
렌더링, 표 그리기, 페이지 높이 측정. 어느 것도 디스크에 저장되는 내용을 결정하지 않습니다.
도형 프리셋 목록조차 Rust 코어에서 읽어오므로, 갤러리에 있는 도형과 포맷이 아는 도형이
어긋날 수 없습니다 (`apps/web/test/shapes.test.js`가 이를 검사합니다).

차트 팔레트는 색각 이상 대비를 검증한 8색 고정 순서이고, 밝은/어두운 배경에 각각 다른 단계를
씁니다. 9번째 계열은 새 색을 만들지 않고 `기타`로 합칩니다.

## API

에이전트나 스크립트가 UI 없이 문서를 다룰 수 있습니다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/health` | 상태와 작업 폴더 |
| `GET` | `/api/projects` | 목록 |
| `POST` | `/api/projects` | 생성 `{ type, title, sample }` |
| `GET` | `/api/projects/:folder` | 전체 내용 |
| `PUT` | `/api/projects/:folder` | 저장 (md/json/AI.md 재생성) |
| `PATCH` | `/api/projects/:folder` | 제목·폴더명 변경 `{ title }` |
| `DELETE` | `/api/projects/:folder` | 삭제 |
| `GET` | `/api/projects/:folder/files` | 파일 목록 |
| `GET` | `/api/projects/:folder/history` | 보관된 버전 목록 (최신순) |
| `POST` | `/api/projects/:folder/restore` | 버전 복원 `{ snapshot }` — 지금 상태를 먼저 보관합니다 |
| `GET` | `/api/projects/:folder/file?path=` | 파일 내용 |
| `GET` | `/api/projects/:folder/digest` | `AI.md` |
| `POST` | `/api/projects/:folder/preview` | 저장하지 않고 쓰일 md/json 확인 |
| `POST` | `/api/import` | Office 파일 가져오기 `{ name, data }` (base64) |
| `GET` | `/api/projects/:folder/export/:ext` | `pptx` · `docx` · `xlsx` · `csv` |
| `GET` `POST` | `/api/projects/:folder/assets` | 이미지 목록 / 업로드 `{ name, dataUrl }` |
| `GET` | `/api/projects/:folder/asset?path=` | 이미지 제공 |
| `POST` | `/api/recalc` | 시트 재계산 `{ cells, names }` |

`PUT` 은 보낸 부분만 반영합니다 — 슬라이드만 고쳐 보내면 매니페스트의 나머지는 디스크의 값을 씁니다.
`PUT` 에 `baseModified`(읽어 온 `manifest.modified`)를 실으면 **낙관적 동시성 검사**가 됩니다:
그 사이 디스크가 바뀌었으면 409를 돌려주고 아무것도 덮어쓰지 않습니다. 에디터는 항상 이것을
싣고, 충돌 시 사용자에게 덮어쓸지 묻습니다. `baseModified` 없이 보내면 예전처럼 그냥 씁니다 —
읽지 않고 쓰기만 하는 에이전트의 경로입니다.
폴더 파라미터는 작업 폴더 밖을 벗어나지 못하도록 검증되고, 자산은 `assets/` 안만 읽힙니다.

데스크톱 앱에서는 같은 함수들이 Tauri 커맨드(`get_project`, `save_project`, …)로 노출되며,
HTTP 서버가 전혀 뜨지 않습니다.

> [받아서 실행하기](#받아서-실행하기)에서 완성된 설치 파일을 내려받으세요. 아래는 소스에서
> **직접 `.exe`(또는 `.dmg`·`.AppImage`)를 만들고 싶을 때**의 안내입니다.

아래 순서를 그대로 따라 하면 됩니다. **① 도구 설치 → ② 소스 내려받기 → ③ 빌드 → ④ 결과 실행**
네 단계이고, 개발 지식이 없어도 복사·붙여넣기로 됩니다. 처음 한 번은 도구를 받느라 10~30분
걸릴 수 있습니다(그 다음부터는 몇 분).

### ① 공통 도구 두 가지

운영체제와 상관없이 이 둘이 필요합니다. 한 번만 설치하면 됩니다.

1. **Rust** — <https://rustup.rs> 에서 안내대로 설치합니다 (기본값 그대로 Enter).
2. **Node.js 20 이상** — <https://nodejs.org> 에서 **LTS** 버전을 받아 설치합니다.

설치가 끝나면 **터미널(Windows는 "PowerShell", macOS는 "터미널", Linux는 셸)** 을 새로 열고
아래를 실행해 둘 다 보이는지 확인합니다. 버전 숫자가 나오면 성공입니다.

```bash
rustc --version      # 예: rustc 1.8x.x
node --version       # 예: v20.x.x
```

### ② 운영체제별 준비물 (한 번만)

데스크톱 앱은 각 OS의 화면 표시 도구가 하나 더 필요합니다. 자기 OS의 것만 하면 됩니다.

### ③ 소스 내려받아 빌드하기

터미널에서 아래를 위에서부터 차례로 실행합니다. `#` 뒤는 설명이니 빼고 붙여 넣어도 됩니다.

```bash
# 1) 소스 내려받고 그 폴더로 이동
git clone <이-저장소-주소> ai-studio
cd ai-studio

# 2) 빌드에 필요한 부품 준비 (처음 한 번, 몇 분 걸림)
rustup target add wasm32-unknown-unknown     # 브라우저용 코어 빌드 대상
cargo install wasm-bindgen-cli tauri-cli     # 빌드 도구 두 개
npm install                                  # 웹 UI 의존성

# 3) 설치 파일 만들기 (여기서 실제 .exe / .dmg / .AppImage 가 나옵니다)
npm run desktop:build
```

`git clone`의 `<이-저장소-주소>`는 이 프로젝트의 실제 주소로 바꿔 넣습니다. zip으로 받았다면
압축을 풀고 그 폴더에서 `cd` 만 하면 됩니다.

### ④ 만들어진 설치 파일 위치

빌드가 끝나면 마지막 줄에 파일 경로가 출력됩니다. 위치는 OS별로 아래와 같습니다
(`AI Studio_0.2.0_...` 부분의 숫자는 버전에 따라 다를 수 있습니다).
| OS | 만들어지는 파일 | 위치 |
|---|---|---|
| Windows | `AI Studio_0.2.0_x64-setup.exe`, `.msi` | `target/release/bundle/nsis/` · `target/release/bundle/msi/` |
| macOS | `AI Studio_0.2.0_aarch64.dmg` | `target/release/bundle/dmg/` |
| Linux | `.AppImage` · `.deb` · `.rpm` | `target/release/bundle/appimage/` 등 |
이 파일을 두 번 눌러 설치하면 일반 프로그램처럼 시작 메뉴·런치패드·앱 목록에 들어갑니다.
**사내에 나눠 줄 때는 이 파일 하나만 전달하면 됩니다** — 받는 사람은 Rust도 Node도 설치할
필요가 없습니다.

### 먼저 켜서 확인만 하고 싶다면 (설치 파일 없이)

설치 파일을 만들기 전에 앱이 뜨는지 바로 보고 싶으면, 개발 모드로 실행합니다. 창이 그대로 뜹니다.

```bash
npm run seed        # 샘플 문서 3개 넣기 (선택)
npm run desktop     # 데스크톱 앱을 개발 모드로 실행
```

### 브라우저·서버로 쓰고 싶다면

데스크톱 앱 대신 브라우저에서 열거나 공유 서버로 두는 방법입니다.

```bash
# 개발 모드 (코드 고치면 바로 반영)
npm run dev         # 서버(5177) + 웹(5178) 동시 실행 → http://localhost:5178

# 프로덕션처럼 한 포트에서

npm run serve       # http://localhost:5177 에서 API와 화면을 함께 제공
```

### 잘 안 될 때 (자주 겪는 오류)

| 증상 | 원인과 해결 |
|---|---|
| `link.exe not found` / `linker not found` (Windows) | ② 단계의 **Visual Studio Build Tools**가 없거나 설치 중 "C++ 데스크톱 개발"을 체크 안 함. 다시 설치하세요. |
| `WebView2 ... not found` / 창이 안 뜸 (Windows) | **WebView2 런타임** 설치 (②의 링크). |
| `cargo: command not found` / `rustc ...` | Rust 설치 후 **터미널을 새로 열지 않음**. 창을 닫고 다시 여세요. |
| `wasm-bindgen` / `cargo tauri` 를 못 찾음 | ③의 `cargo install wasm-bindgen-cli tauri-cli` 를 건너뜀. 다시 실행하세요. |
| `npm: command not found` | Node.js가 설치 안 됨(①). LTS를 다시 설치하고 터미널을 새로 여세요. |
| Linux에서 `webkit2gtk` 관련 오류 | ②의 `apt-get install ...` 줄을 실행하지 않음. |
| 그 외 | `npm test` 로 코어가 정상인지 먼저 확인하면 문제 범위를 좁힐 수 있습니다(아래 [검증](#검증)). |

## 검증

```bash
npm test                 # Rust 449개 + 웹 85개
npm run e2e              # API·디스크 검증 100개 (서버 실행 중일 때)
npm run smoke            # 실제 React 앱을 jsdom에 마운트, 291개
```

- **`cargo test`** — 수식 엔진(원래 JS 스위트를 그대로 이식한 34개 포함), 포맷 왕복, 경로 탈출 차단,
  그리고 **만들어진 Office 파일의 zip을 풀어 XML을 검사**합니다: 수식이 값이 아니라 수식으로 나갔는지,
  병합·틀 고정·이름 범위가 각 형식의 요소로 변환됐는지, pptx에 네이티브 차트 파트와 편집 가능한
  `a:tbl`이 생겼는지, 모든 관계(`_rels`)가 실제로 존재하는 파트를 가리키는지.
- **수식은 Excel의 값과 맞춰 검사합니다.** 재무·통계·날짜·찾기 함수 100여 개를 표로 놓고 자리
  넷까지 비교하고, 등록된 이름 215개가 하나도 `#NAME?`을 내지 않는지도 확인합니다 — 목록에는
  있는데 구현이 없는 함수는 수식 입력창이 깨뜨리는 약속이기 때문입니다.
- **가져오기는 양방향으로 검사합니다.** 이 프로젝트가 쓴 파일을 다시 읽어 두 모델이 일치하는지
  보고(작성기가 내는데 판독기가 버리는 것이 바로 드러납니다), 실제 파일에만 있는 것들 —
  자리틀 좌표 상속, 테마 색, 마스터의 글머리 기호, 그룹 좌표 변환, 스타일에 든 목록 정의,
  Word의 세로 병합 — 은 손으로 만든 최소 패키지로 확인합니다.
- **`npm run e2e`** — 세 문서 타입을 실제로 만들고 편집해 저장한 뒤 **디스크에 쓰인 파일**을 열어
  확인합니다. 좌표가 md로 새지 않는지, 텍스트가 json으로 새지 않는지, 손으로 고친 마크다운이 다시
  열리는지, 경로 탈출이 막히는지까지.
- **`npm run smoke`** — 렌더링뿐 아니라 편집 상호작용까지: 셀 입력이 의존 수식을 연쇄 재계산하는지,
  자동 채우기가 등차수열을 이어가는지, `F5`가 슬라이드 쇼를 띄우고 방향키로 넘어가는지, 차트 삽입이
  SVG를 그리는지, 페이지 나누기가 페이지를 늘리는지. 도형 갤러리에서 고른 뒤 **캔버스에 끌어
  그려지는지**, 상황별 탭이 붙고 사라지는지, 셀을 누르면 커서가 들어가고 `Tab`이 다음 칸으로
  가는지, 리본의 **탭과 그룹 이름·순서가 Office 그대로인지**, 용지를 가로로 돌리면 비율이 뒤바뀌는지,
  4:3 덱이 4:3으로(썸네일까지) 열리고 크기를 직접 입력하면 도형이 캔버스 안으로 들어오는지, 색 팔레트가
  테마 색 60개와 표준 색 10개로 열리는지, **메뉴가 리본 밖(`document.body`)에 그려져 잘리지 않는지**도
  검사합니다. `jsdom`과 `esbuild`가
  필요합니다.

```bash
npm i -D jsdom esbuild
AI_STUDIO_TOOLS=$(pwd) npm run smoke
```

- **`scripts/snapshot.mjs`** — 같은 방식으로 앱을 띄워 **화면을 한 장의 HTML로** 떠 옵니다. 실제
  가져오기를 거친 실제 에디터의 DOM에 앱의 스타일시트와 글꼴을 함께 담으므로, 브라우저에서 열면
  화면을 그대로 볼 수 있습니다 (누를 수는 없습니다).

```bash
python3 scripts/make-fixtures.py out/          # Office 파일 8개 생성
AI_STUDIO_API=http://localhost:5177 \
AI_STUDIO_TOOLS=$(pwd) node scripts/snapshot.mjs out/ screens.html
```

만들어진 `.xlsx`/`.pptx`/`.docx`는 `openpyxl`·`python-pptx`·`python-docx`로도 열어 확인했습니다
(수식·표시 형식·틀 고정·이름 범위, 네이티브 차트의 계열과 항목, A4 용지와 여백, 제목 스타일).
반대 방향도 확인했습니다 — 같은 라이브러리들로 **다른 구현이 만든** pptx·docx·xlsx를 생성해
가져오기에 넣었고, 수식·서식·병합·틀 고정·이름 범위, 자리틀 상속 좌표, 테마 색, 도형 프리셋,
표 병합, 차트 숫자, 목록 단계가 모두 넘어옵니다.
브라우저를 띄워 눈으로 확인한 것은 아닙니다 — 이 개발 환경에 headless 브라우저를 실행할 시스템
라이브러리가 없어서, 렌더링 검증은 jsdom까지입니다.

## 현재 한계

- **`.docx`·`.xlsx`에는 네이티브 차트가 없습니다.** `.pptx`만 편집 가능한 차트로 나가고, Word는 차트를
  데이터 표 + 캡션으로, Excel은 데이터 블록으로 씁니다. Word/Excel의 차트는 별도의 임베디드 워크북
  파트를 함께 써야 하는데, 차트가 이미 시트 범위를 가리키는 이 포맷에서는 숫자를 그대로 넘기는 편이
  받는 사람에게 더 쓸모 있습니다.
- **PDF는 브라우저 인쇄로 만듭니다.** 세 앱 모두 `Ctrl+P`가 동작합니다 — Doc은 페이지
  그대로, Deck은 슬라이드마다 한 장(덱 비율에 맞는 용지 방향), Grid는 사용 중인 범위를
  Excel처럼(눈금선 없이, 지정한 테두리·서식만) 인쇄합니다. 별도의 PDF 엔진은 없습니다.
- **실시간 동시 편집은 없습니다.** 대신 두 가지가 그 자리를 지킵니다: 저장은 낙관적 동시성
  검사를 거치고(다른 곳에서 먼저 저장했으면 409 → 에디터가 덮어쓸지 물음), **편집하지 않고
  보고 있는 문서는 다른 곳의 저장을 몇 초 안에 스스로 따라옵니다** — 에이전트가 API로 문서를
  고치는 동안 화면이 낡은 채 남지 않습니다. 두 사람이 같은 문단을 실시간으로 함께 고치는
  것은 지원하지 않습니다.
- **Doc의 페이지 나눔은 블록 단위입니다.** 한 문단이 페이지 경계를 넘으면 문단 전체가 다음 장으로
  넘어갑니다(Word와 같은 동작). 다만 페이지보다 큰 문단은 잘리지 않고 그 페이지를 넘칩니다.
- **머리글·바닥글은 한 줄 세 칸입니다.** 페이지마다 다른 머리글(첫 페이지만 다르게, 짝/홀수)과
  각주·목차 자동 생성은 없습니다. `.docx`의 `default` 머리글·바닥글을 읽고 다시 씁니다.
- **셀 서식 대화상자, 조건부 서식, 필터가 없습니다.** 정렬은 선택 범위의 첫 열 기준만 지원합니다.
  `.xlsx`를 가져올 때 조건부 서식·데이터 유효성 검사·자동 필터는 넘어오지 않습니다(셀 값과 서식은
  그대로 옵니다).
- **`.xlsx`의 그림은 넘어오지 않습니다.** 차트는 넘어옵니다(범위를 가리키는 살아 있는 차트로).
- **각주·미주는 문장의 ¹ 표시 + 섹션 끝 모음으로 바뀝니다.** 페이지마다 그 페이지의 각주를
  아래에 두는 Word의 배치는 아닙니다. 검토 주석(메모)은 넘어오지 않습니다.
- **애니메이션·화면 전환이 없습니다.** pptx를 가져올 때도 무시됩니다.
- **가져올 때 일부는 가장 가까운 것으로 바뀝니다** — SmartArt는 도형들로, OLE 개체는 미리보기
  그림으로, 그라데이션은 중간 색의 단색으로, 분산형·방사형 차트는 꺾은선으로. 위의 변환 표를
  참고하세요. 워드아트의 글자 효과는 평범한 글자가 됩니다.
- **도형 프리셋 136개를 그립니다.** OOXML에는 그보다 많고, 모르는 프리셋은 경계 사각형으로
  그려집니다. 다만 **이름은 그대로 보존**되므로 내보내면 PowerPoint에서 제 모양으로 돌아옵니다.
- **조절 핸들은 프리셋 34종에 붙습니다.** Office처럼 조절할 것이 없는 도형(사각형, 타원, 별 등)에는
  붙지 않고, 가져온 `adjust` 값은 어느 도형이든 유지되고 그려집니다.
- **도형 효과(그림자·반사·네온)와 그라데이션 채우기를 만들 수는 없습니다.** 색은 Office의 팔레트로
  고르지만 채우기는 단색뿐이고, 가져온 그라데이션은 중간 색의 단색이 됩니다. 스포이트(화면 색 추출)도
  없습니다.
- **표에서 셀 범위 선택(끌어서 여러 셀)은 없습니다.** 병합은 리본의 "오른쪽과 병합" · "아래와 병합"
  으로 합니다.
- **글꼴은 하나입니다.** 원본이 요구한 글꼴은 모두 Pretendard로 바뀌어 열립니다 (무엇을 바꿨는지는
  알려 줍니다). 글꼴이 바뀌면 글자 폭도 바뀌므로, 원본에서 한 줄에 꼭 맞던 문장이 한 글자 넘칠 수
  있습니다. PowerPoint가 줄여 넣은 기록(`normAutofit`)은 반영하지만, 그 외의 자동 줄바꿈 차이까지
  맞추지는 않습니다.
- **문단 안에서 크기가 섞인 경우는 첫 서식을 따릅니다.** 한 도형·문단의 글자 크기·색·굵기는 하나이고,
  첫 런의 것을 씁니다(굵게·기울임·취소선·링크는 런 단위로 마크다운에 남습니다).
