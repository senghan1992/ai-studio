# AI Studio 파일 포맷 스펙 v1

## 설계 원칙

1. **프로젝트는 폴더다.** 단일 바이너리(zip) 파일이 아니라 일반 디렉터리. `git diff`가 동작하고, `grep`이 동작하고, RAG 인덱서가 파일 단위로 청킹할 수 있다.
2. **내용은 Markdown, 배치는 JSON.** 사람이 읽는 텍스트/의미는 `.md`, 좌표·스타일·계산은 `.json`. 둘은 **블록 ID**로 연결된다.
3. **Markdown은 손으로 고칠 수 있다.** md만 편집해도 앱이 열린다 (없는 배치는 자동 레이아웃으로 채움).
4. **JSON은 진실의 원천(source of truth)이고, md는 투영(projection)이다.** 단 텍스트 내용에 관해서는 md가 원천이다. 겹치지 않게 역할을 나눈다.
5. **`AI.md`는 자동 생성 다이제스트.** 프로젝트 전체를 한 파일로 요약해 LLM 컨텍스트에 그대로 넣을 수 있게 한다.

## 공통 구조

```
<Title>.aideck/          # 프레젠테이션
<Title>.aidoc/           # 문서
<Title>.aigrid/          # 스프레드시트
├── manifest.json        # 문서 타입, 순서, 테마, 메타데이터
├── AI.md                # ⚙️ 자동 생성 — RAG/LLM용 전체 다이제스트
├── slides|content|sheets/
│   ├── 01-title.md          # 내용 (Markdown)
│   └── 01-title.layout.json # 배치/스타일 (JSON)
└── assets/              # 이미지 등 바이너리
```

### manifest.json (공통 필드)

```json
{
  "format": "ai-studio/deck",
  "formatVersion": 1,
  "id": "prj_k3n8x1",
  "title": "Q3 Business Review",
  "created": "2026-09-01T04:30:00.000Z",
  "modified": "2026-09-01T05:12:44.000Z",
  "theme": { "name": "aurora", "accent": "#4f46e5", "font": "Inter" }
}
```

타입별 추가 필드: `slides[]` / `sections[]` / `sheets[]` — 각 항목은 `{ id, name, md, json }` 경로 쌍.

## 1. Deck (`.aideck`) — 프레젠테이션

핵심: **슬라이드 1장 = md 1개 + layout.json 1개.**

### `slides/01-title.md`

```markdown
---
id: s1
title: 표지
layout: title
notes: |
  인사하고 3분 안에 아젠다로 넘어간다.
---

<!-- block:b1 -->
# 2026 3분기 사업 리뷰

<!-- block:b2 -->
매출 성장과 신규 시장 진입 결과 보고

<!-- block:b3 -->
![팀 사진](../assets/team.png)
```

* 블록 구분자는 `<!-- block:ID -->`. HTML 주석이므로 어떤 Markdown 렌더러에서도 안전하게 무시된다.
* 블록 안의 내용은 **평범한 Markdown**이다 (제목, 리스트, 표, 이미지, 코드펜스).
* 프론트매터의 `notes`는 발표자 노트 → LLM이 화자 의도를 읽을 수 있다.
* `layout`은 의미적 레이아웃 이름 (`title`, `title-content`, `two-column`, `blank`).

### `slides/01-title.layout.json`

```json
{
  "id": "s1",
  "canvas": { "w": 1280, "h": 720, "bg": "#ffffff" },
  "blocks": {
    "b1": { "x": 96, "y": 220, "w": 1088, "h": 120, "z": 1, "kind": "text",
            "style": { "fontSize": 56, "weight": 700, "align": "center", "color": "#111827" } },
    "b2": { "x": 96, "y": 360, "w": 1088, "h": 60, "z": 2, "kind": "text",
            "style": { "fontSize": 22, "align": "center", "color": "#6b7280" } },
    "b3": { "x": 440, "y": 440, "w": 400, "h": 220, "z": 3, "kind": "image",
            "style": { "fit": "cover", "radius": 12 } }
  }
}
```

`kind`: `text` | `image` | `shape` | `table` | `chart`.
좌표계는 캔버스 픽셀 기준 (기본 1280×720, 16:9).

## 2. Doc (`.aidoc`) — 문서

핵심: **섹션 1개 = md 1개 + meta.json 1개.** 흐름(flow) 레이아웃이므로 x/y 좌표가 없고, 대신 **문서 구조와 스타일 오버라이드**를 JSON이 갖는다.

### `content/01-intro.md`

깨끗한 순수 Markdown이다. 기본 스타일을 쓰는 문단에는 주석조차 없다.

```markdown
---
id: sec1
name: 서론
---

# 서론

이 문서는 AI Studio의 저장 포맷을 설명한다.

<!-- block:p7 -->
> 인용문처럼 특별한 서식이 붙은 문단만 ID 주석을 갖는다.

## 배경

- 기존 오피스 포맷은 zip + XML이다
- LLM이 직접 읽기 어렵다
```

* **ID 주석은 비-기본 서식을 가진 블록에만 붙는다.** 덕분에 md가 지저분해지지 않는다.

### `content/01-intro.meta.json`

```json
{
  "id": "sec1",
  "page": { "size": "A4", "margin": { "top": 72, "right": 72, "bottom": 72, "left": 72 } },
  "blocks": {
    "p7": { "align": "center", "indent": 36, "spacing": { "before": 12, "after": 12 },
            "style": { "italic": true, "color": "#4f46e5" } }
  },
  "outline": [
    { "level": 1, "text": "서론", "anchor": "서론" },
    { "level": 2, "text": "배경", "anchor": "배경" }
  ],
  "stats": { "words": 42, "chars": 231 }
}
```

`page.header` · `page.footer`는 세 칸(`left` · `center` · `right`)이고, `{PAGE}` · `{PAGES}` ·
`{DATE}`가 페이지마다 치환된다. 내보낼 때 Word의 `PAGE`/`NUMPAGES` 필드가 되고, 가져올 때 그
필드가 다시 토큰이 된다 — 그래서 페이지가 늘어나도 번호가 맞는다. 빈 칸은 기록하지 않는다.

```json
"page": { "size": "A4", "footer": { "center": "{PAGE} / {PAGES}", "right": "기밀" } }
```

`page.size`는 용지 이름(`A3` · `A4` · `A5` · `B5` · `Letter` · `Legal` · `사용자 지정`)이고,
`page.width` · `page.height`는 px 크기다. **크기가 있으면 이름보다 크기가 이긴다.**

```json
"page": { "size": "A4", "width": 1123, "height": 794 }   // 가로 A4
"page": { "size": "사용자 지정", "width": 680, "height": 945 }   // 180×250mm 소책자
```

세로 방향의 이름 있는 용지는 크기를 적지 않는다 — 이름이 이미 말하고 있고, 적으면 기존 파일이
전부 바뀐다. 이름 하나로는 "돌려 놓은 A4"를 표현할 수 없어서 둘 다 필요하다. 가로/세로는 파생
값이다: `width > height`면 가로다.

## 3. Grid (`.aigrid`) — 스프레드시트

핵심: **JSON이 계산의 원천, md는 사람·AI가 읽는 투영.**
md에는 **계산된 값**이 A/B/C 열 머리글과 1/2/3 행 번호와 함께 들어간다 → LLM이 "B5" 같은 셀 주소로 추론할 수 있다.

### `sheets/sales.md` (자동 생성 투영)

```markdown
---
id: sh1
name: 매출
dims: { rows: 6, cols: 4 }
---

## 매출

|   | A | B | C | D |
|---|---|---|---|---|
| **1** | 지역 | 1분기 | 2분기 | 합계 |
| **2** | 동부 | 1,200 | 1,350 | 2,550 |
| **3** | 서부 | 980 | 1,120 | 2,100 |
| **4** | **총계** | **2,180** | **2,470** | **4,650** |

### 수식

- `D2` = `=B2+C2` → 2550
- `D3` = `=B3+C3` → 2100
- `B4` = `=SUM(B2:B3)` → 2180
- `C4` = `=SUM(C2:C3)` → 2470
- `D4` = `=SUM(D2:D3)` → 4650

### 이름 있는 범위

- `매출데이터` → `A1:D4`
```

### `sheets/sales.cells.json` (원천)

```json
{
  "id": "sh1",
  "name": "매출",
  "dims": { "rows": 200, "cols": 26 },
  "frozen": { "rows": 1, "cols": 1 },
  "colWidths": { "A": 120 },
  "rowHeights": {},
  "cells": {
    "A1": { "v": "지역", "t": "s", "style": { "bold": true, "bg": "#f3f4f6" } },
    "B2": { "v": 1200, "t": "n", "fmt": "#,##0" },
    "D2": { "f": "=B2+C2", "v": 2550, "t": "n", "fmt": "#,##0" },
    "B4": { "f": "=SUM(B2:B3)", "v": 2180, "t": "n", "style": { "bold": true } }
  },
  "merges": [],
  "names": { "매출데이터": "A1:D4" }
}
```

* `f` = 수식, `v` = 마지막으로 계산된 값(캐시), `t` = 타입(`n`/`s`/`b`/`d`/`e`), `fmt` = 표시 형식.
* 수식 캐시 `v`가 있으므로 **계산 엔진 없이도** md 투영과 RAG가 정확한 값을 본다.
* 수식은 시트를 넘을 수 있다 — `=실적!B4`, `=SUM('2분기 실적'!A1:D9)`. 이름 있는 범위도 다른
  시트를 가리킬 수 있고(`"매출범위": "데이터!B1:B3"`), 워크북 전체에서 쓰이는 이름은 모든 시트의
  `names`에 들어간다(이 포맷에는 워크북 수준의 이름이 없다).
* `charts[]`는 `range`를 가리키는 살아 있는 차트다. 범위가 풀리지 않을 때만 `series`에 남은 값을
  그린다.
* `style`은 `bold` · `italic` · `underline` · `color` · `bg` · `align` · `border` · `fontSize`(px).
  `fontSize`는 시트 기본 크기(`grid::CELL_PX` = 15px, Excel의 11pt)와 다를 때만 적힌다.

## 4. `AI.md` — RAG 다이제스트

저장할 때마다 자동 재생성된다. 프로젝트 전체를 하나의 마크다운으로 평탄화하며, LLM이 알아야 할 구조 정보(슬라이드 순서, 블록 위치의 의미, 수식)를 자연어로 붙인다.

```markdown
# Q3 Business Review
> AI Studio Deck · 슬라이드 3장 · 최종 수정 2026-09-01

## 슬라이드 1 — 표지 (layout: title)
발표자 노트: 인사하고 3분 안에 아젠다로 넘어간다.

### 2026 3분기 사업 리뷰
_위치: 상단 중앙_

매출 성장과 신규 시장 진입 결과 보고
_위치: 중앙_
```

위치를 픽셀이 아니라 **`상단 중앙`, `좌측 하단` 같은 자연어**로 번역하는 것이 핵심이다. LLM은 좌표보다 이 표현을 훨씬 잘 이해한다.

## 5. 도형

도형의 어휘는 **OOXML의 `prstGeom` 프리셋 이름 그대로**다. `roundRect`, `flowChartDecision`,
`rightArrow` 같은 이름을 새로 만들지 않고 채택했기 때문에 `.pptx`를 열면 그 모양으로 보이고,
다시 내보내면 같은 이름으로 나간다.

텍스트는 언제나 md에, 모양은 언제나 JSON에 있다. 도형 안의 글자는 그 블록의 마크다운이다.

`slides/03-순서도.md`

```markdown
<!-- block:b_7k2mx -->
승인?
```

`slides/03-순서도.layout.json`

```json
{
  "blocks": {
    "b_7k2mx": {
      "x": 96, "y": 96, "w": 288, "h": 192, "z": 1, "kind": "shape",
      "style": { "align": "center", "valign": "middle", "fontSize": 18 },
      "shape": {
        "preset": "flowChartDecision",
        "fill": { "color": "#dbeafe" },
        "line": { "color": "#2a78d6", "width": 2, "dash": "dash" },
        "rotation": 15,
        "flipH": true,
        "adjust": { "adj": 20000 }
      }
    }
  }
}
```

* `preset` — `prstGeom` 이름. **렌더러가 모르는 이름도 그대로 보존된다.** 이름을 잃으면 그 도형은
  영구히 사각형으로 강등되지만, 보존하면 파일이 왕복하고 나중에 그릴 수도 있다.
* `fill` 없음 = 채우기 없음, `line` 없음 = 윤곽선 없음. "말하지 않음"과 "없다고 말함"은 다르다.
* `adjust` — `prstGeom`의 조절 핸들. OOXML의 1/100000 단위를 그대로 쓴다.
* `rotation` — 시계 방향 각도. `flipH`/`flipV`는 좌우·상하 반전.

`AI.md`는 도형을 이름으로 부른다. 그래야 순서도가 순서도로 읽힌다.

```markdown
### 1) 도형(판단) — 상단 좌측, 좁은 폭

승인?
```

## 6. 표

**셀의 글자는 마크다운 표에, 배치는 JSON에.** 이 포맷의 나머지와 같은 규칙이다. 덕분에 표가
`grep`에 걸리고, 에이전트가 행을 추가하려면 행을 한 줄 쓰면 된다.

`slides/04-비교.md`

```markdown
<!-- block:b_tbl -->
| 항목 | 상반기 |  |
|---|---:|---:|
| 제품 A | 1,200 | 1,350 |
| 제품 B | 980 | 1,120 |
```

`slides/04-비교.layout.json`

```json
{
  "blocks": {
    "b_tbl": {
      "x": 96, "y": 144, "w": 768, "h": 192, "z": 1, "kind": "table",
      "table": {
        "cols": [288, 240, 240],
        "rows": [40, 32, 32],
        "merges": ["B1:C1"],
        "headerRow": true,
        "bandedRows": true,
        "firstCol": false,
        "style": "banded"
      }
    }
  }
}
```

* 셀 주소는 스프레드시트와 같다. **머리글 행이 1행**이다.
* `merges` — 합쳐진 영역. 글자는 좌상단 셀에 있고 나머지 칸은 마크다운에서 비어 있다.
* `style` — `banded`(줄무늬) · `plain`(격자) · `borderless`(테두리 없음).
* **정렬은 마크다운이 결정한다.** `|---:|`을 손으로 고치면 그대로 반영되고, JSON의 낡은
  `align`은 무시된다. 마크다운이 표현할 수 있는 것은 마크다운이 원천이라는 원칙이다.

두 가지 제약을 분명히 해 둔다.

* 셀의 글자는 **한 줄**이다. 셀 안 줄바꿈은 GFM과 같이 `<br>`로 저장된다.
* 기본 배치인 표는 JSON을 갖지 않는다. Doc에서는 `<!-- block:id -->` 앵커도 붙지 않아
  md가 순수 마크다운으로 남는다.

### 구조 편집은 md와 JSON을 함께 바꾼다

행이나 열을 넣고 빼면 셀 배열만 움직이는 것이 아니다. `merges`의 범위와 `cells`의 주소도 같이
따라와야 한다. 이건 행을 삽입하면 `=SUM(B2:B4)`가 `=SUM(B3:B5)`가 되어야 하는 것과 정확히 같은
문제이고, 틀리면 **구멍 난 표**가 그려진다. 그래서 편집은 에디터가 아니라 포맷이 한다
(`crates/ai-format/src/table.rs`의 `Table`).

| 편집 | md | merges | cells |
|---|---|---|---|
| 행/열 삽입 | 빈 줄/칸 삽입 | 삽입 지점 뒤로 이동 | 주소 이동 |
| 행/열 삭제 | 제거 | 걸친 병합은 축소, 안에 든 병합은 소멸 | 삭제된 줄의 항목은 제거 |
| 병합 | 모든 글자를 좌상단으로 모음 | 겹치는 기존 병합을 대체 | — |
| 병합 해제 | 그대로 | 덮고 있던 범위 제거 | — |

병합할 때 덮이는 셀의 글자는 **버리지 않고 좌상단에 모은다.** Office도 그렇게 하고, 저장한 뒤에는
되돌리기로 되찾을 수 없기 때문이다. 세로로만 걸친 병합이 한 행으로 줄면 병합이 아니게 되므로
사라진다.

## 7. 기존 Office 파일 열기

`.pptx` · `.docx` · `.xlsx`를 이 포맷으로 **한 방향으로** 변환한다. 원본은 건드리지 않고
새 폴더 문서를 만든다. 제자리에서 고쳐 다시 `.pptx`로 저장하는 것은 이 포맷이 존재하는 이유를
포기하는 일이므로, 돌아가는 길은 내보내기다.

| 원본 | 결과 | 좌표 |
|---|---|---|
| `.pptx` | `.aideck` | **정확히 일치** — EMU ÷ 914400 × 96 |
| `.xlsx` | `.aigrid` | 해당 없음 (수식·서식이 그대로) |
| `.docx` | `.aidoc` | 흐름 문서이므로 의미 단위로 대응 |

pptx에서 넘어오는 것: 자리틀 상속 좌표, 도형 프리셋·채우기·윤곽선·회전·반전, 테마 색,
마스터의 글머리 기호, 표(열 너비·병합·정렬), 네이티브 차트의 숫자, 그림, 발표자 노트, 그룹 변환.

### 슬라이드 크기는 파일이 정한다

`p:sldSz`가 캔버스다. 16:9(12192000 × 6858000)는 그중 하나일 뿐이고, 4:3·세로 A4·정사각형·직접
입력한 크기가 모두 그대로 들어온다. 편집 화면의 캔버스, 왼쪽 썸네일의 비율, 슬라이드 쇼, 내보내는
`p:sldSz`가 모두 이 하나의 값에서 나온다.

자리틀이 **상속한** 좌표가 캔버스를 넘치면 안으로 들인다. 파일이 만들어진 뒤 크기만 바뀌면
(PowerPoint 아닌 도구가 흔히 그렇게 한다) 레이아웃은 옛 크기에 맞춰져 있고, 745px 슬라이드에 864px
제목은 보여줄 방법이 없다. 도형이 **스스로 말한** 좌표는 손대지 않는다.

### 머리글·바닥글 자리틀은 내용이 있을 때만 그린다

모든 Office 템플릿은 날짜·바닥글·슬라이드 번호 자리틀을 필드만 담은 채로 싣고 다닌다. 그것을 그대로
가져오면 저자가 켠 적 없는 날짜(`1/27/13`)와 페이지 번호가 모든 슬라이드에 찍힌다. 그래서 레이아웃의
이 세 자리틀은 **사람이 입력한 글자가 있을 때**, 또는 `p:hf`가 보이라고 말할 때만 블록이 된다.
저자가 실제로 켜면 PowerPoint가 자리틀을 슬라이드마다 복사해 넣으므로, 그때는 슬라이드에서 읽힌다.

### 서식은 슬라이드에 없다

실제 pptx는 서식을 슬라이드에 적어 두지 않는다. 판독기는 Office와 같은 순서로 해석한다.

```
런 rPr → 문단 pPr/defRPr → 도형 txBody/lstStyle → 레이아웃 자리틀 lstStyle
                                                → 마스터 txStyles/{title,body,other}Style
```

레벨(`lvl`)마다 따로 정의되고, **필드 단위로** 합쳐진다 — 레이아웃이 크기만 바꿨다면 색과 굵기는
마스터의 것이 남는다. `b="0"`처럼 "아니라고 말한 것"은 "말하지 않은 것"과 구분한다.

레이아웃·마스터의 **자리틀이 아닌 도형**(띠·선·로고)은 슬라이드 블록보다 낮은 `z`로 함께 들어온다.
자리틀은 건너뛴다 — 그 안의 글자는 "제목을 입력하십시오" 같은 안내문이다. 슬라이드가
`showMasterSp="0"`이라고 말했으면 마스터 도형은 넣지 않는다.

배경은 슬라이드 → 레이아웃 → 마스터 순으로 찾는다. 대부분의 덱은 슬라이드에 배경을 적지 않는다.

`normAutofit fontScale`은 PowerPoint가 글자를 줄여 넣은 기록이므로 크기에 곱한다.

### 워크북에서 잃기 쉬운 세 가지

**공유 수식.** Excel은 끌어서 채운 수식을 한 번만 쓴다 — 범위의 좌상단 셀에 텍스트를 쓰고, 나머지
셀에는 `<f t="shared" si="0"/>`만 남긴다. 텍스트만 읽으면 저자가 드래그로 채운 셀 전부, 즉 대개
대부분의 수식이 사라진다. 판독기는 `si`로 원본을 찾아 상대 참조를 옮긴다.

**시트를 넘는 참조.** 요약 시트는 `=실적!B4`로만 이루어져 있다. 렉서가 `Sheet!A1`을 한 토큰으로
읽고, 평가기가 워크북의 다른 시트를 함께 받는다. 넘겨받지 못한 시트를 가리키면 **셀에 있던 값을
그대로 둔다** (아래).

**차트.** `xl/charts/`의 차트 파트와 `xl/drawings/`의 앵커로 나뉘어 있다. 앵커의 (열, 행) + EMU
오프셋을 이 시트의 실제 열 너비로 픽셀로 바꾸고, 계열이 가리키는 범위를 `range`로 삼는다 —
워크북 안의 차트는 자기 셀을 가리키므로 값을 복사할 이유가 없다.

### 없는 기능은 가장 가까운 것으로 바꾼다

이 포맷에 없는 것을 만나면 세 가지 중 하나를 한다. 순서대로 시도한다.

1. **같은 것으로 바꾼다.** SmartArt는 Office가 파일에 함께 그려 둔 `dsp:sp` 도형들이 되고, OLE
   개체는 그 자리의 미리보기 그림이 되고, 사진으로 채운 도형은 그 사진이 된다.
2. **가장 가까운 것으로 바꾼다.** 분산형·방사형 차트는 꺾은선이 되고(숫자는 그대로), 그라데이션은
   중간 색의 단색이 되고, 각주는 문장의 `¹`와 구분선 아래의 작은 문단이 되고, 조건부 서식은 저장된
   값 기준의 고정 서식이 된다.
3. **바꿀 수 없으면 이름을 대고 알린다.** "데이터 막대·아이콘 집합은 표현할 방법이 없어
   넘어갔습니다" — 무엇이 없는지 아는 쪽이 언제나 낫다.

침묵은 세 번째 선택지가 아니다. 지운 것을 말하지 않으면, 읽는 사람은 원본과 화면을 눈으로
비교하며 무엇이 달라졌는지 찾아야 한다.

### 다시 계산할 수 없으면 파일의 값을 남긴다

없는 함수(`#NAME?`)나 넘겨받지 못한 시트(`#REF!`)를 만난 수식은 **저장된 값을 덮어쓰지 않는다.**
`recalc`는 그런 셀을 `unresolved`로 보고하고 값은 손대지 않는다. 사용자가 방금 입력한 수식에는
남길 값이 없으므로 오류가 그대로 보인다 — 감추는 것이 아니라, 이미 있는 답을 지우지 않는 것이다.

### 글꼴은 하나다

원본이 요구한 글꼴(`a:latin`·`w:rFonts`·`<name val>`)은 읽지만 저장하지 않는다. 이 포맷의 글꼴은
하나(`manifest.theme.font`, 기본 `Pretendard`)이고, 앱이 그 글꼴 파일을 담아 배포한다. 어느
운영체제에서 열어도 같은 모양이 되는 대신, 글자 폭이 원본과 달라질 수 있다. 무엇을 바꿨는지는
가져오기 경고로 보고한다.

단, **고정폭 글꼴은 이름 대신 뜻으로 남는다** — Consolas·Courier로 쓰인 런은 마크다운의
`` `코드` ``가 된다. `Symbol`·`Wingdings`는 글머리 기호의 글꼴이므로 목록 마커가 되고 보고하지
않는다.

### 크기 기준값은 스타일시트와 한 곳에서 나온다

가져오기는 "앱이 어차피 그렸을 크기"와 비교해서, 다른 것만 적는다. 그래서 11pt 본문 문단은
서식 표시가 붙지 않고 마크다운이 깨끗하게 남는다.

| 상수 | 값 | 대응하는 CSS |
|---|---|---|
| `doc::BODY_PX` | 15 | `.md--doc { font-size: 15px }` |
| `doc::heading_px(1..4)` | 25 · 20 · 16.5 · 15.75 | `.md--doc h1`…`h4` |
| `grid::CELL_PX` | 15 | 시트 표의 기본 글자 크기 |
| `mdblocks::HEADING_EM` | 1.9 · 1.5 · 1.2 · 1.05 | `.md h1`…`h4` (슬라이드) |
| `mdblocks::NESTED_LIST_EM` | 0.875 | `.md--slide ul ul` |

블록이 자기 크기를 적었으면 그 크기가 그대로 그려진다(`md--sized`). 제목 배율을 다시 곱하면
Word의 16pt 제목이 40px이 되기 때문이다.

옮겨지지 않는 것은 침묵하지 않고 보고한다 — "그라데이션 채우기는 첫 색으로 단순화했습니다",
"SmartArt·OLE 개체는 가져오지 못했습니다", "글꼴은 모두 Pretendard로 바꿔 열었습니다 (Calibri)".

## 왜 이게 AI에게 유리한가

| | OOXML (.pptx/.docx/.xlsx) | AI Studio |
|---|---|---|
| 컨테이너 | zip + 수십 개 XML 파트 | 일반 폴더 |
| 텍스트 추출 | XML 파싱 필요, 런(run) 단위로 조각남 | md 그대로 읽으면 끝 |
| 위치 정보 | EMU 단위 좌표, 도형 트리 | JSON + 자연어 번역 |
| 청킹 단위 | 파일 전체 | 슬라이드/섹션/시트 = 파일 1개 |
| 버전 관리 | 바이너리 diff | 텍스트 diff |
| 수식 | 계산 결과가 별도 캐시 파트에 | `f`와 `v`가 한 객체에 |
